# Local UI

The ESP32 owns the display. The browser is a remote control; no screen content is
rendered in the browser (the browser only mirrors the device framebuffer).

## Framebuffer

- `ui::fb[15000]`: 400×300, 1bpp, 50 bytes/row, MSB left.
- **1 = white, 0 = black** (same as the panel).
- `panel42::shadow[15000]` tracks what is currently on the panel.
- After drawing a screen, `commit()` compares `fb` and `shadow` byte-by-byte:
  - no difference → nothing sent;
  - small rectangle → `partialFb()` (0.58 s, partial waveform);
  - large rectangle / forced → `fullStd()` (0.98 s, full waveform).
- The compare is byte-granular; the window is aligned to 8 pixels.

## Screens

### Home

- Four rows: **时钟 / 记事 / 图片 / 设置**.
- Icon + Chinese label + inverted selection bar.
- `↑↓` move, `OK` enter, `Back/Home` return.
- Menu movement uses a full standard refresh (~1 s) to keep the selection bar and
  icons clean.

### Clock

- NTP (`CST-8`), big `HH:MM`, date and weekday, NTP status.
- **Full standard refresh once per minute**, static in between; no seconds.
- Reason: the old 4.2 partial waveform fades the whole panel after ~35 s of 1 Hz
  updates. See [INVESTIGATION.md](INVESTIGATION.md#4-why-the-clock-cannot-update-every-second).
- At the minute boundary the panel flashes for ~1 s; this is the cost of keeping
  the image clean.

### Notes

- Text comes from the web page (`POST /api/note`), UTF-8.
- Wraps at 360 px; 9 lines/page; `↑↓`/`←→` page.
- Stored in NVS namespace `pda`, key `note`; survives reboot.
- Empty state shows a hint.
- Body limit 4095 bytes; the page textarea limits to 1200 characters.
- Page turns use a full standard refresh (~1 s).

### Image

- `/api/full?mode=fast|std|hq` uploads a full 1bpp frame and switches to this app.
- The image is kept in RAM only (`hasImage`), so it is lost on reboot.
- Back/Home returns to the menu; entering the image app again redraws it with a
  full standard refresh.

### Settings

- Wi-Fi SSID, IP, RSSI, free heap, current panel mode, flash size, uptime, web URL.
- Status bar minute updates use a small partial window; a full refresh happens
  every 15 minutes.

## Font

`ui_font.h` is generated by `tools/gen_font.py` from **GNU Unifont 16 px**:

- 7447 GB2312 characters / punctuation, 16×16, 32 bytes per glyph.
- 95 printable ASCII, 8×16, 16 bytes per glyph.
- 1 = ink, MSB left.
- Missing characters (outside GB2312, emoji) render as a hollow box.
- The table lives in flash and adds ~270 KB to the app.

Regenerate on a machine with the Unifont OTF installed:

```bash
python3 tools/gen_font.py
# writes firmware/epaper42_web/ui_font.h
```

## Web remote

- `GET /api/screen`: 15,000-byte raw frame; page draws it into a canvas.
- `GET /api/ui`: app, selection, page count, last refresh time.
- `POST /api/key?k=...`, `POST /api/app?name=...`.
- Note textarea: `GET/POST /api/note`.
- Preview polls every 1.5 s; key/app actions refresh immediately.
- Buttons are disabled while a refresh is in flight (the server is single
  threaded and a refresh takes 0.58–0.98 s).

## Memory / storage

- `fb` + `imageFb` + driver `shadow` + HTTP body buffer ≈ 60 KB.
- Font bitmaps ≈ 270 KB flash.
- App size ≈ 1.09 MB of the 1.31 MB partition (83%).
- NVS note; no LittleFS image persistence yet.

## Extending

- Add GPIO buttons and call `ui::key("up"|"down"|"ok"|"back")`.
- Add a reader/text editor screen; reuse `layoutText`/`drawText`.
- Persist images in LittleFS (15 KB each).
- If you move to a 4.2 V2 panel, the partial waveform can be driven faster; the
  UI/HTTP layers can stay.
